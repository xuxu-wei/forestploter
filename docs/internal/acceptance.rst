实施计划与验收标准
==================

本页把 v0.1 的需求拆成可独立核对的交付门禁。每项能力必须同时有输入契约、
结构断言和可查看产物；仅凭“能生成一张图”不视为通过。

实施边界
--------

本阶段采用一条记录描述“一个系列在一个 CI 列中的一次观察”的长表模型。读取器
保留 XLSX 的值、物理行顺序和单列纵向合并结构，CSV 使用相同字段但没有合并
信息。Excel 的字体、颜色、边框、行高和列宽不参与渲染；效应量和置信区间也必须
由调用方预先计算。

核心技术字段固定为 ``_plot_row``、``_series``、``_ci_column``、``estimate``、
``lower``、``upper``、``_row_type``、``_indent`` 和 ``_is_summary``。多系列通过
增加记录而不是增加 ``3*k`` 数值列来表达；同一系列跨多个 CI 列时复制记录并
复用同一个 ``_plot_row``。

实施顺序与门禁
--------------

.. list-table::
   :header-rows: 1
   :widths: 16 34 28 22

   * - 阶段
     - 交付内容
     - 自动门禁
     - 人工核对
   * - A. 文件边界
     - ``read_forest_data``、字段映射、XLSX 合并与源坐标、CSV 等价输入
     - 工作表/表头定位、公式缓存、空行、非法合并和源坐标测试
     - 模板中的 ``Forest`` 与 ``README`` 工作表可理解、可编辑
   * - B. 数据语义
     - ``_plot_row`` 唯一控制纵坐标；同一视觉行的系列、行类型、缩进、汇总标志
       和显示值必须一致
     - 连续性、跨 CI 唯一性、空白三元数和字段类型测试
     - 多系列文字行与对应 CI 线逐行共线
   * - C. 渲染与布局
     - 合并单元格居中、内部横线抑制、越界箭头、表头/底部图例和布局诊断
     - artist 结构、几何边界、截断计数、图例范围及 PNG/SVG 导出测试
     - 桌面与窄屏文档页面可读；十三张回归图无视觉错位
   * - D. 文档与交付
     - pandas/NumPy 风格 docstring、Sphinx API、数据契约、迁移说明、图库和路线图
     - pytest、严格 Sphinx HTML、doctest、wheel 安装烟雾测试全部通过
     - API 页面、图库导航和移动端代码/表格滚动正常

逐项验收矩阵
------------

.. list-table::
   :header-rows: 1
   :widths: 31 43 26

   * - 用户场景
     - 可重复的验收证据
     - 通过标准
   * - 越界侧不出现竖直端帽
     - 检查单侧截断和完全越界区间的 Matplotlib artist；核对截断压力图
     - 箭头替代越界侧端帽；完全越界只保留一个向外箭头
   * - 合并单元格共享一个居中值
     - 检查读取到的 ``ForestCellSpan``、合并文字 y 坐标和被抑制的内部分界线
     - 合并值只出现一次，位于完整跨度中心，跨度内无穿越文字的横线
   * - 多系列只使用三列区间数值
     - 检查所有 XLSX/CSV 表头和多系列规范化观察数
     - 每条记录只有 ``estimate/lower/upper``；不出现系列专属三元数组
   * - 空白记录不绘制区间
     - 对三元数全空和部分空白分别测试
     - 全空时显式跳过；只空一部分时给出带记录位置的错误
   * - 多系列、多 CI 列严格对齐
     - 比较 ``layout_diagnostics.observation_positions`` 中相同
       ``(_plot_row, _series)`` 的 y 坐标
     - 所有目标 CI 列的 y 完全相等，不由各列分别计算偏移
   * - 每系列有独立置信区间文本行
     - 核对 ``12_multi_series_ci_text_rows`` 的 21 条源记录、文字 artist 与 CI artist
     - 每条未合并文本和对应系列 CI 使用同一视觉行中心
   * - 图例可放表头或底部
     - 分别测试指定任意列的表头图例、指定列的底部图例及跨全部活动 CI 列的底部图例
     - 图例边界位于目标列或目标列组内，多图例自动堆叠且不重叠
   * - CSV 与 XLSX 兼容
     - 十三组同名输入逐组比较 ``plot_row_ids``、观察位置和截断计数
     - 规范化绘图语义相同；CSV 不推断合并或前向填充
   * - 数据、图片名称可追踪
     - 检查十三组 ``.xlsx``、``.csv``、``.png`` 的同名映射
     - 每个用例三个产物具有同一文件名主体且数量一一对应
   * - API 文档随版本更新
     - 严格构建 Sphinx ``autodoc``/``autosummary`` 并核对公开对象清单
     - 当前 ``__all__`` 全部有独立 API 页面，零警告、零失效交叉引用

自动化执行
----------

在项目根目录运行：

.. code-block:: powershell

   python -m pytest tests -q
   python -m sphinx -M html docs docs/_build -W
   python -m sphinx -b doctest docs docs/_build/doctest -W

pytest 必须零失败、零 ``xfail``。严格 HTML 构建必须零警告；doctest 必须全部
通过。十三组规范输入都要成功导出 PNG 和 SVG；生成文件不得覆盖输入工作簿。

人工视觉清单
------------

自动断言通过后，再打开 ``docs/_build/html/index.html`` 完成以下检查：

#. 桌面宽度约 1440 px：侧栏、站内导航、API 字段列表和十三张图库图片完整可读。
#. 窄屏宽度约 390 px：菜单可展开，代码块和宽表可局部横向滚动，页面本身不产生
   持续横向溢出。
#. 重点核对 ``04_clipping_stress``、``08_two_by_two_ci_columns``、
   ``12_multi_series_ci_text_rows`` 和 ``13_comprehensive_showcase``：箭头端帽、
   多列共线、逐系列文字行、父标题与缩进子行层级、单列额外目标线、方向指示和
   底部图例均符合预期；第 13 例不得包含合并单元格。
#. 打开 ``tests/data/forest_data_template.xlsx``，确认 README 对三元数、
   ``_plot_row``、合法合并、空白值和公式缓存的说明足以独立完成首次录入。

只有自动门禁全部通过且上述人工项目有明确结论时，才将里程碑标记为完成。
